# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Button, Separator, Avatar, Progress, Meter.
> Generated by gsd-ui-researcher. Consumed by gsd-planner, gsd-executor, gsd-ui-auditor.

---

## Phase Scope Note

Phase 1 implements five Base UI primitive wrappers as single-file `.tsx` components distributed via the bct-ui registry. This is a **component library phase**, not an application UI phase. The "design contract" governs:

1. Which BCT token maps to which component state for each of the 5 components
2. Size tier dimensions (sm/md/lg/xl) for Button and Avatar
3. Typography within components (button labels, avatar fallback initials, progress/meter labels)
4. Animation contract for Progress indeterminate state
5. Visual differentiation rules between Progress and Meter
6. Copywriting: fallback text, aria-label conventions, destructive button copy

No new tokens may be introduced. All styling references CSS variables from `packages/ui/src/assets/tokens/index.css`.

## Spacing Scale

Source: `packages/ui/src/assets/tokens/index.css` — `--spacing: 0.25rem` (4px base unit). Tailwind utilities map directly to multiples of this unit.

| Token | Value | Phase 1 Usage |
|-------|-------|---------------|
| xs | 4px (1 unit) | Icon-to-content gap inside Button (`gap-1`) |
| sm | 8px (2 units) | Progress/Meter label gap |
| md | 16px (4 units) | Button `md` horizontal padding (`px-4`); default internal padding |
| lg | 24px (6 units) | Button `lg` horizontal padding (`px-6`) |
| xl | 32px (8 units) | Not used in Phase 1 |
| 2xl | 48px (12 units) | Not used in Phase 1 |
| 3xl | 64px (16 units) | Not used in Phase 1 |

Button `sm` horizontal padding is `px-3` (12px) — see Component Props Contract size table below, which is authoritative for per-size padding values.

Exceptions:
- Touch target minimum: Button height at every size must be at minimum 44px per WCAG 2.5.5. Enforced via `h-8 min-h-8` for sm (32px — acceptable for non-touch contexts; document in props comments that `sm` is below WCAG touch target), `h-10` for md (40px — borderline; acceptable), `h-12` for lg (48px — compliant). No new tokens required; use existing Tailwind height utilities.
- Avatar `icon` variant: Icon button produces equal width/height square. Sizes: `h-8 w-8` sm, `h-10 w-10` md, `h-12 w-12` lg. Zero horizontal padding (`p-0`). Source: 0.4.0 Button `sizeStyles` pattern, 01-CONTEXT.md specifics.

## Typography

Source: `packages/ui/src/assets/tokens/index.css` `@layer base` global typography rules. All token values verified by direct file read.

| Role | Token / Size | Weight Token | Weight | Line Height | Phase 1 Usage |
|------|-------------|--------------|--------|-------------|---------------|
| Button label | `--text-sm` / 14px (sm/md), `--text-base` / 16px (lg) | `--font-weight-bold` | 700 | n/a (single line) | Button children text |
| All other component text | `--text-sm` / 14px | `--font-weight-normal` | 400 | 1.5 | Avatar fallback initials, Meter visible label, Progress aria-label |

Active weights in Phase 1: **400 (normal)** and **700 (bold)** — exactly 2 weights. Button uses bold (matches global `.button` class in `index.css`). Avatar fallback initials, Meter label, and Progress label all use 400/normal weight. No intermediate 500/medium weight is used in Phase 1.

Font family: `var(--font-sans)` ("Quicksand") for all component text. No serif usage in Phase 1.

|-------------|-----------|------------|-----------|

| md | `size-10` (40px) | `text-sm` (14px) | `size-5` (20px) |
| lg | `size-12` (48px) | `text-base` (16px) | `size-6` (24px) |

Source: 0.4.0 `avatar.tsx` `sizeStyles` and `iconSizeStyles` maps — carried forward per D-04.

## Color

Source: `packages/ui/src/assets/tokens/index.css` `:root` (light) and `.dark` / `[data-theme="dark"]` blocks. All values below are light-theme values; dark-theme counterparts exist for every token.

| Role | Token | Light Value | Phase 1 Usage |
|------|-------|-------------|---------------|
| Dominant surface (60%) | `--color-background` | `#f4f2ef` | Page context (set by consumer) |
| Secondary surface (30%) | `--color-surface-2` | `#f8f8f8` | Avatar fallback background |
| Accent (10%) | `--color-primary` | `#21459b` | Primary button fill; Progress/Meter fill bar |
| Destructive | `--color-error` | `#cc5c5c` | Button `error` variant fill |

**Accent reserved for (explicit list):**
- `primary` Button variant fill (`bg-primary`) and hover (`bg-primary-hover`)
- Focus ring on all interactive elements (`ring-primary-focus`, `--color-primary-focus` = `#3b82f6`)
- Progress bar fill (determinate): `bg-primary`
- Meter bar fill: `bg-primary` (default; single-color uniform fill per D-06)

### Button Variant → Token Map

| Variant | Background | Text | Hover background |
|---------|------------|------|-----------------|
| `primary` | `bg-primary` | `text-primary-on` | `bg-primary-hover` |
| `secondary` | `bg-secondary` | `text-secondary-on` | `bg-secondary-hover` |
| `tertiary` | `bg-tertiary` + `border-border` | `text-tertiary-on` | `bg-tertiary-hover` + `border-border-hover` |
| `error` | `bg-error` | `text-error-on` | `bg-error-hover` |
| `success` | `bg-success` | `text-success-on` | `bg-success-hover` |
| `warning` | `bg-warning` | `text-warning-on` | `bg-warning-hover` |
| `info` | `bg-info` | `text-info-on` | `bg-info-hover` |
| `text` | transparent | `text-typography-primary` | `bg-surface-1-hover` |
| `icon` | transparent | `text-typography-primary` | `bg-surface-1-hover` |

**Token value confirmation for status variants (verified in `index.css` `:root` and `.dark`):**

| Token | Light value | Dark value | Executor note |
|-------|------------|-----------|---------------|
| `--color-info-on` | `#ffffff` | `#ffffff` | Token has values — use `text-info-on` directly |
| `--color-success-on` | `#ffffff` | `#ffffff` | Token has values — use `text-success-on` directly |
| `--color-warning-on` | `#000000` (dark text on yellow) | `#000000` | Token has values — use `text-warning-on` directly |
| `--color-error-on` | `#ffffff` | `#ffffff` | Token has values — use `text-error-on` directly |

All four status `-on` tokens are defined in both `:root` and `.dark` in `index.css`. No token gaps exist for status variant text. No additions to `index.css` are required for status button text colors.

Note: 0.4.0 `text` and `icon` variants used `bg-accent` for hover — this token is not in the BCT token set. Replace with `bg-surface-1-hover` (XCUT-01 compliance). Source: 0.4.0 `button.tsx` lines 115–124 cross-referenced with `index.css` token audit.

**Disabled state (all variants):** `disabled:opacity-50 disabled:pointer-events-none disabled:cursor-not-allowed`. No separate disabled-color override needed — opacity approach is consistent with 0.4.0.

**Active/press state (all solid variants):** `active:scale-[0.98]` + `active:bg-{variant}-focus` where the focus token exists, else `active:bg-{variant}-hover`.

Focus token availability by variant:
- `primary`, `secondary`, `tertiary` — have `-focus` tokens in `index.css`; use `active:bg-{variant}-focus`
- `info`, `success`, `warning`, `error` — have NO `-focus` tokens in `index.css`; use `active:bg-{variant}-hover` for these variants

### Avatar Token Map

| State | Token | Usage |
|-------|-------|-------|
| Fallback container background | `bg-surface-2` | When no image or image fails |
| Fallback initials text | `text-typography-primary` | Text fallback rendering |
| Fallback icon color | `text-typography-muted` | `<User />` Lucide icon fill |

### Progress Token Map

| Part | Token | Usage |
|------|-------|-------|
| Track (background) | `bg-surface-2` or `bg-border` | The unfilled bar rail |
| Fill (determinate) | `bg-primary` | Filled portion at `value` |
| Indeterminate animation | `bct-progress-indeterminate` CSS class | Applied when `value={null}` via `[data-indeterminate]` selector |
| Border radius | `rounded-full` | Both track and fill bar |

### Meter Token Map

| Part | Token | Usage |
|------|-------|-------|
| Track (background) | `bg-surface-2` | The unfilled bar rail |
| Fill | `bg-primary` | Filled portion (single color, no zones per D-06) |
| Label text | `text-typography-secondary` | Visible `label` prop text above bar |
| Border radius | `rounded-full` | Both track and fill bar |

**Visual differentiation between Progress and Meter** (Claude's discretion per 01-CONTEXT.md):
- Progress: no visible label rendered (label is `aria-label` only); track uses `bg-border` (lighter, more subtle)
- Meter: always renders visible `label` prop as `<span>` above the bar; track uses `bg-surface-2` (same as Avatar fallback background)
- Height: Progress track is `h-2` (8px); Meter track is `h-3` (12px) — slightly taller to signal it's a measurement, not a task progress indicator

### Separator Token Map

| Part | Token | Usage |
|------|-------|-------|
| Line color | `bg-divider` (for block-level separator) | Horizontal or vertical rule |
| Spacing around separator | `my-2` horizontal, `mx-2` vertical | Default margin |

## Copywriting Contract

### Button

| Variant | Default label guidance | aria-label guidance |
|---------|----------------------|---------------------|
| `icon` variant | No text children — always provide `aria-label` | `aria-label="[action name]"` e.g. `aria-label="Close"` |
| `error` variant | Destructive action label: sentence case, explicit verb — "Delete item", "Remove file", "Revoke access" | No separate aria-label needed if button text is descriptive |
| `text` variant | Sentence case — "Learn more", "View details" | No separate aria-label needed |
| All other variants | Sentence case — "Save changes", "Submit form" | No separate aria-label needed |

**Destructive action confirmation:** Button component itself does not render a confirmation dialog. That is AlertDialog's responsibility (Phase 5). Button `error` variant is used as the confirm action inside AlertDialog when needed.

### Avatar

| State | Copy |
|-------|------|
| Fallback initials | Derived from `alt` prop: first letter of each word, uppercased, max 2 characters. Example: `alt="Jonas Blendstrup"` → "JB". If no `alt` and no `fallback`, renders `fallbackIcon` with no text. |
| Fallback icon alt | `<User />` icon is decorative — no alt text needed; parent element `aria-label` from consumer |
| Image alt | Passed through to `<img alt={alt}>` verbatim. Defaults to `"Avatar"` when `alt` is undefined. |

### Progress

| State | Copy |
|-------|------|
| `label` prop | Passed as `aria-label` to `<BaseProgress.Root>` — screen-reader only. Recommended consumer copy: "[task name] progress" e.g. `label="Upload progress"`. Component does not render label visually. |
| Indeterminate (`value={null}`) | `aria-label` still required from consumer. Recommended: "Loading" or the task name. |

### Meter

| State | Copy |
|-------|------|
| `label` prop | Rendered as visible `<span>` above the bar AND passed as `aria-label`. Required for accessibility. Recommended consumer copy: noun describing what is being measured, e.g. "Storage used", "Disk space", "Battery level". |
| Value display | No numeric value text rendered by default. Consumer can pass value display content as children or via `classNames.label` override. |

### Separator

| Usage | Copy |
|-------|------|
| Semantic separator | `aria-orientation` is set automatically by Base UI from `orientation` prop. No additional copy required. |
| Decorative separator (default) | `decorative` prop defaults to `false` (semantic by default). Consumer passes `decorative` when used purely as a visual element — in that case Base UI renders `role="none"`. |

## Component Props Contract

This section documents the exact prop interface design decisions for each Phase 1 component. The executor uses this as the implementation spec.

### Button

```
variant?: "primary" | "secondary" | "tertiary" | "error" | "success" | "warning" | "info" | "text" | "icon"
  default: "primary"
  source: D-01 (01-CONTEXT.md) — exactly 9 variants; no -muted siblings

size?: "sm" | "md" | "lg"
  default: "md"

className?: string
  applies to: BaseButton root element

classNames?: { root?: string }
  note: Button is a single-element component — only root slot is relevant
```

Size dimension table (authoritative for all per-size values including padding):

| Size | Height | Padding (non-icon) | Padding (icon variant) | Text size |
|------|--------|--------------------|------------------------|-----------|
| sm | `h-8` (32px) | `px-3` (12px) | `w-8 p-0` | `text-sm` |
| md | `h-10` (40px) | `px-4` (16px) | `w-10 p-0` | `text-base` |
| lg | `h-12` (48px) | `px-6` (24px) | `w-12 p-0` | `text-lg` |

Source: 0.4.0 `button.tsx` `sizeStyles` map — carried forward unchanged for all sizes.

### Separator

```
orientation?: "horizontal" | "vertical"
  default: "horizontal"

decorative?: boolean
  default: false  (semantic separator — renders role="separator"; a11y-correct default per Claude's discretion)

className?: string
classNames?: { root?: string }
```

Visual dimensions:
- Horizontal: `w-full h-px` (1px height, full container width)
- Vertical: `h-full w-px` (1px width, full container height)
- Color: `bg-divider`

### Avatar

```
src?: string
alt?: string
fallback?: string           — explicit fallback text override (1–2 chars recommended)
fallbackIcon?: React.ReactNode
  default: <User className="text-typography-muted" /> sized per iconSizeStyles[size]
  null = hide icon entirely
  source: D-03 (01-CONTEXT.md)

size?: "sm" | "md" | "lg" | "xl"
  default: "md"
  source: D-04 (01-CONTEXT.md)

shape?: "circle" | "square"
  default: "circle"
  source: D-04 (01-CONTEXT.md)

className?: string
classNames?: { root?: string; image?: string; fallback?: string }
```

Fallback resolution priority:
1. If `src` provided and image loads successfully: render image
2. If `src` provided but image fails: check `fallback` text, then derive initials from `alt`, then render `fallbackIcon`
3. If no `src`: check `fallback` text, then derive initials from `alt`, then render `fallbackIcon`

Requires `"use client"` directive — Base UI Avatar.Image tracks load state internally.

### Progress

```
value?: number | null
  default: 0
  null = indeterminate state (Base UI sets data-indeterminate; animation via .bct-progress-indeterminate CSS class)
  source: D-05 (01-CONTEXT.md)

min?: number
  default: 0

max?: number
  default: 100

label?: string
  usage: passed as aria-label to BaseProgress.Root — NOT rendered visually

className?: string
classNames?: { root?: string; indicator?: string }
  root = the track element
  indicator = the fill bar element
```

Requires `"use client"` directive — Base UI Progress uses controlled state.

### Meter

```
value: number    (required — Meter always shows a measured value)
min?: number
  default: 0
max?: number
  default: 100
label?: string   (strongly recommended for a11y — renders as visible <span> AND aria-label)

className?: string
classNames?: { root?: string; indicator?: string; label?: string }
  root = the track element
  indicator = the fill bar
  label = the visible label <span>
```

Note: `value` is required for Meter (it is a measurement display). No indeterminate state — measurements always have a known value. Source: D-06 (01-CONTEXT.md) and FOUND-05 requirement.

## Animation Contract

### Progress Indeterminate

New CSS class to add to `packages/ui/src/assets/tokens/index.css`:

```css
/* ─── BCT Progress animations ───────────────────────────────────────────────── */

@keyframes progress-indeterminate {
  0% { transform: translateX(-100%); }
  50% { transform: translateX(0%); }
  100% { transform: translateX(100%); }
}

.bct-progress-indeterminate [data-indeterminate] {
  animation: progress-indeterminate 1.5s ease-in-out infinite;
  width: 40%;
}
```

Naming follows the `bct-*` pattern established in Phase 0 (D-04 of 00-CONTEXT.md). The `[data-indeterminate]` selector targets the indicator element that Base UI decorates when `value` is `null`. Duration: 1.5s matches common indeterminate loader conventions. No `forwards` fill-mode needed because this is an infinite loop, not a one-shot open/close animation.

Executor must add this CSS block to `index.css` as part of Phase 1 — it is the only CSS change in this phase.
